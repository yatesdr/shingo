# The goroutines in Core's engine and dispatch that Engine.Stop does not wait
# for, each with why it need not or must not. Read by the repolint rule
# bare-goroutines (shared/scripts/repolint/sites.go), which fails a go
# statement or AfterFunc call in a function no line here allows, and a line
# that counts more than the tree has.
#
# Stop waits for the engine's own loops and hand-offs, spawned on its tracked
# group (e.loops.spawn; TestEngineStop_WaitsForItsGoroutines). A bare go
# statement or an AfterFunc timer is outside that wait: still running after
# Stop, it reads a database its caller is about to close and logs through a
# logger whose owner may be gone (docket B4). This list is where they are
# named; the comment on Engine.loops (shingo-core/engine/engine.go) points
# here.
#
# scope <dir>                            read, with the directories under it
# go <file>:<func> <count> <why>         that many go statements in that function
# AfterFunc <file>:<func> <count> <why>  that many calls named AfterFunc in it

scope shingo-core/engine
scope shingo-core/dispatch

go shingo-core/engine/engine_lifecycle.go:stopBounded 1 Stop's own waiter: it runs stopAndWait so that Stop can return at its deadline whatever is still running, so it cannot be in the group it waits for (TestEngineStop_OneDeadlineOverEveryWait)
go shingo-core/engine/engine_lifecycle.go:tableTurnAlarm 1 the table-turn alarm's e-mail send: Stop never waits on a mail server; the send reads no database and logs through the process log, not the engine's
go shingo-core/engine/sourceability_monitor.go:Run 1 the sourceability monitor's ticker: the monitor counts each pass (begin) and its stop waits for one running (TestSourceabilityMonitor_StopWaitsForARunningRecompute)
AfterFunc shingo-core/engine/sourceability_monitor.go:arm 1 the sourceability monitor's debounce: its stop cancels an armed one and waits for a flush already running (TestSourceabilityMonitor_StopCancelsAnArmedDebounce)
go shingo-core/engine/wiring.go:wireEventHandlers 3 the fault-cleared, failed and grace-expired e-mail sends: Stop never waits on a mail server; a send reads no database and logs through the process log, not the engine's
AfterFunc shingo-core/engine/wiring.go:wireEventHandlers 1 the fault e-mail's timer (faultTimers): it waits three minutes, longer than Stop does, then sends mail; it reads no database
