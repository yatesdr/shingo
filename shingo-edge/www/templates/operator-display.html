{{/* BOOT WATCHDOG — deliberately a classic inline script, not a module. createSSE already reloads a long-lived board when the build id changes, and that is the right mechanism. Its flaw is location: it lives INSIDE the module graph it protects, so it is reachable only if operator.js links. A syntax error anywhere in that graph disables the graph AND its own recovery, and the board sits on the "Loading..." placeholder above until somebody walks the floor. That is exactly what happened at Hopkinsville on 2026-09-08. Inline and dependency-free, this cannot be taken down by any module failure. It arms only when the graph did NOT boot, so a healthy board never opens a second EventSource. It waits for the build id to CHANGE rather than reloading straight away: re-loading a broken build just re-breaks and spins. Sitting quietly until a fix is actually deployed is the useful behaviour — and it makes `systemctl restart shingo-edge` a fleet-wide "reload every HMI", since serverInstance is what the id is cut from. */}}
